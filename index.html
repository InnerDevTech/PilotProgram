MVP and stretch goals

The MVP is what must be done for a successful project:

  • Sprint 1: buttons, knob, clock, timer and stopwatch.
  • Sprint 2: hand dot from the IR beams.
  • Sprint 3: rings on registered objects, calibrated.

Stretch goals, only after the MVP demo passes:

  • Sprint 4: balls and physics.
  • More beams, or a second hand.
  • Speech for object names.
  • A saved log of what was on the desk and when.

If time runs short, cut stretch goals first. Never cut the sprint demo or the docs.

How a sprint runs

Every sprint follows the same four steps.

  1. Plan (day 1, 30 minutes). Choose the tasks from the sprint table, put them in TO DO, write the goal on the board, agree the demo date.
  2. Build (days 2 to 8). Stand-up at the start of each session. Move cards as they progress. Ask for help early.
  3. Demo (day 9 or 10). Run the demo checklist. Each tick is a pass. Failures become new cards in the next sprint's TO DO.
  4. Reflect (last session, 20 minutes). What went well? What did not? What will we change next sprint?

Write the answers in docs/sprint-reviews/S<number>.md, and the day-to-day record in that sprint's wiki page under "What actually happened".

The board has these columns, plus a Risks column added in Sprint 0:

BACKLOG | TO DO (this sprint) | DOING | TESTING | DONE

Project done definition

  • Every sprint demo checklist has passed at least once.
  • The Sprint 5 "new person" test passed.
  • Both test suites pass.
  • The Build Guide, README and wiki match the code.
  • The showcase has been given and the reflection is saved.
